# 吞咽事件采集与端侧分类 —— 上位机 App

课程设计「颈部吞咽相关事件的采集、传输与端侧智能分类」的上位机骨架。
现在这个版本负责**采数据**，分类那一栏故意留成占位。

## 现在能干什么

- 48 kHz / 单声道 / 16 bit 录音，**强制关闭系统自动增益、降噪、回声消除**
  （任务书要求，否则咳嗽冲击被压平、吞咽低频被削掉）
- 实时滚动波形，20 fps 刷新，窗口约 10 s
- 录完直接落成标准 WAV，文件名带类别前缀：`swallow_20261125_103000.wav`
- 「记录」页可导出（微信/邮件/文件管理器）和删除
- 「分类」页是占位：界面、指标位都留好了，接 TFLite 时只改一个类

## 对应评分项

| 评分项 | 这个 App 提供什么 |
|---|---|
| 3 传输与实时显示（15） | 波形滚动、采样率/峰值显示、连接状态位 |
| 4 数据集（10） | 按类别命名、静息段可单独录、导出原始 WAV |
| 6 端侧部署（15） | 分类页已留模型体积/推理时延/端到端时延三个指标位 |

## 采数据怎么用

1. 首页「采集」页，上方选类别：吞咽 / 咳嗽 / 干扰 / 静息
2. 点「开始录音」，做动作，前后各留 1 秒静息，停 2～3 秒后点「停止并保存」
3. 每类每人 ≥ 10 条，8 人共 ≥ 240 条（任务书硬指标）
4. 录完到「记录」页，用导出按钮把所有 WAV 发到电脑

类别对应关系（任务书三类 + 静息）：

| 文件名前缀 | 含义 | 是否进分类指标 |
|---|---|---|
| `swallow_` | 干咽或定量饮水吞咽 | 是 |
| `cough_` | 单次主动咳嗽 | 是 |
| `interfere_` | 说话、清嗓、深呼吸、头动 | 是（负类） |
| `rest_` | 静息无事件 | 否，只算误触发率 |

## 编译

仓库里故意不放 `android/`（几百个文件、随 Flutter 版本变），CI 里现场生成。

```bash
# 本地
flutter create --project-name swallow_monitor --platforms=android /tmp/app
cp pubspec.yaml /tmp/app/ && cp -r lib/. /tmp/app/lib/
python3 tools/prepare_android.py /tmp/app
cd /tmp/app && flutter build apk --release
```

或者推到 GitHub，Actions 自动出 `swallow-monitor.apk`（打 `v*` 标签会挂到 Release）。

## 还没做的（按顺序）

1. **BLE 帧解析**：等固件的 v0 协议（帧头/时间戳/通道号/数据域/CRC），
   在 `lib/core/` 加一个 `ble_source.dart`，波形直接共用一个 `peaks` 缓冲
2. **事件分割**：能量/双阈值，窗 0.5～1.5 s、步长 ≤ 50% 窗长
3. **TFLite 推理**：见 `lib/core/classifier.dart` 顶部注释，五步
4. **时延打点**：从采样到出结果，目标 ≤ 20 ms，模型 ≤ 5 MB
